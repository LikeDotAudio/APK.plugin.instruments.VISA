| **Malformed input is said, never swallowed.** | `BrokenGui` in `generate_device_apis.py` | — |
| **One resolver, as data.** | `families.json`; `family_directory` reads it | other repos' readers adopt it (handoffs) |
| **One repository per family.** Each `INSTRUMENT.<Family>` is its own repo (a submodule at the same path, history kept) and stands almost alone: its models, its panel, its own wiki and SDK, and a `thing.json` saying what it is on the bench — **inputs**, **metering**, **monitoring**, **source**. Readers keep reading paths, so nothing that bakes `INSTRUMENTS` changed. | `.gitmodules`; each family's `thing.json`; `_komand/family_sdk_docs.py` (`--check`, in the root `instruments` lane) writes each family's README and `Documentation/🧩Manual and Artifacts/SDK*` from its `<Model>.api.json` | Cloning needs `--recurse-submodules`; a family edit is a commit there plus a pointer bump here |
| **The SDK is the whole surface — inputs and outputs at three levels.** Each model's SDK page says what goes in and comes out of the **box** (its connectors, from its BIM part — the one place a device type is described, never copied here by hand), of the **API** (each command's arguments, range, choices and unit; what it returns) and of the **bus** (the topic a command arrives on, `<box>/Reading/<command>` where its answer is published), and how to drive it honestly: KOMAND's two messages, raw SCPI through `/api/instrument/send`; the HTTP verb routes only describe. | `_komand/family_sdk_docs.py` (`io_section` reads `DATABASE.server.BIM/SRC/library` beside this checkout; `arg_text`, `out_text`, `drive_section`) | A checkout without the BIM library keeps each page's `<!-- sdk:io -->` block as it is, so `--check` agrees either way; a model with no BIM part says so on its page |
| **A model is a folder that holds its own `<Model>.gui`.** Not "any folder but `gui/`": a family repo also carries `Documentation/`, and counting it would mint a `Documentation.api.json` and shift every later port. | `generate_device_apis.py` (the `devs` list), `family_sdk_docs.py` `load_models()`; `NODE.BareMetal` `instrument_launcher.py`, `crate_tests.py` | Rust walkers look for `.gui` files and `gui/manifest.json`, so a docs folder is invisible to them already |
| **GRAB is compiled from single commands that worked, never from the table** (owner, 2026-11-04). A model's `GRAB` stacks every query a unit on the bench answered ALONE, with the evidence (`<Model>.qualified.json`: which units, when; what was refused) committed beside the tables. It is then run on those units and kept only when every answer comes back (`grab_qualified`). A query the table lists but no unit has answered is not in it, because one unknown header spoils a stacked answer. `*IDN?` and `*OPT?` go last (IEEE 488.2 §8.7.3). A long GRAB is also published as buffer-sized `GRAB_1…n`. It is a NAB, so every reader of `nab` has it without a new verb. | `_komand/compile_grab.py` (evidence → file), `generate_device_apis.py` `grab_endpoints` (file → endpoints), `_komand/qualify_grab.py` (endpoints → proof on the bench); `test_instruments.Grab` | A model with no bench evidence has no GRAB, so the library's GRABs are only as wide as the bench that qualified them |
| **Every instrument is grabbed — settings, every measurement, and what appears only under stimulus** (owner, 2026-11-04; root Doctrine *Every instrument is grabbed*). Settings: `nab/GRAB` above. Measurements: the ROUND ROBIN (WEB.OsApi `capture_round_robin.py`) cycles each MEASure query a model declares — a DMM's DC V, AC V, DC I, Ω, 4W Ω, Hz, period, continuity, diode; a supply's volts and amps — one at a time, always, one graph each over time. Stimulus then grab: an LCR applies its test signal, triggers, fetches — the sequence is the model's table's, never guessed. A model with no GRAB says why (`_komand/check_grab.py`). | `_komand/check_grab.py`, WEB.OsApi `capture_round_robin.py` |
